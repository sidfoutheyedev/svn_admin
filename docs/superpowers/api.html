Brand

Manages the brand catalog — affiliate and onboarded brands shown to shoppers, including their listing status and revenue performance. Routes live in src/brand/brand.routes.ts, mounted at /v1/brands.

🔒
Every route in this module requires authentication. Send Authorization: Bearer <token>. The token must decode to a user with role: "admin" — anything else returns 401 Unauthorized (see src/middlewares/auth.middleware.ts).

Category

Manages the product category tree — top-level categories and their sub-categories. Routes live in src/category/category.routes.ts, mounted at /v1/categories.

🔒
Every route in this module requires authentication. Send Authorization: Bearer <token>. The token must decode to a user with role: "admin" — anything else returns 401 Unauthorized (see src/middlewares/auth.middleware.ts).
POST /v1/categories
Admin

Creates a category. Body is validated against categorySchema. Passing sub_category_names creates its children in the same call.

Request body

Field Type Notes
category_namerequired string min length 1; stored lowercased
category_imagerequired string min length 1 — only required at the top level (see note below)
category_description string | null
parent_id string | null accepted by the schema, but not by CategoryCreateRequest — set it via Update category instead
sub_category_names string[] optional — creates one child category per name
status "Draft" | "Live" | "Hidden" defaults to "Live" at the DB layer

Routes live in src/varient/varient.routes.ts, mounted at /v1/varients. Preferences

Maps storefront merchandising priority to a category — which brands to feature for it and in what order. Routes live in src/preferences/preferences.routes.ts, mounted at /v1/preferences. Distinct from UserPreferences (src/models/user_preferences.model.ts) — a per-shopper personalization score table that has no routes of its own in this codebase.

🔒
Every route in this module requires authentication. Send Authorization: Bearer <token>. The token must decode to a user with role: "admin" — anything else returns 401 Unauthorized (see src/middlewares/auth.middleware.ts).
POST /v1/preferences
Admin

Creates a preference row. Beyond schema validation, the service runs three real-data checks before writing.

Request body

Field Type Notes
category_idrequired string must exist, belong to a top-level category, and have no active preference already
brand_idsrequired string[] schema allows an empty array (no .min(1)) — every id given must exist
priorityrequired number integer, 1–10
status "Draft" | "Live" | "Hidden" defaults to "Draft" — unlike Brand/Category/Variant, which default to "Live"
ℹ
Three checks run in the service, not the schema:
  • 409 if category_id already has a non-deleted preference (also enforced by a partial unique index)
  • 404 "Category not found" if category_id doesn't resolve to a live document
  • 400 "A preference must reference a main category, not a sub-category" if that category has a parent_id — see Category
  • 400 "One or more brand_ids do not exist" if any id in brand_ids doesn't match a non-deleted brand

The stock ledger — a read-only window onto per-variant stock levels and the movement history behind them. Routes live in src/inventory/inventory.routes.ts, mounted at /v1/inventory. There's no schema file for this module because none of its 3 routes take a body.

ℹ
Stock only ever moves through two internal functions this module doesn't expose as routes. inventoryService.recordInbound/recordOutbound (inventory.services.ts:129-134) are called directly by other modules' services, not through any HTTP endpoint here: Create product and Create variant call recordInbound with reason: "STOCKS ADJUSTED" for opening stock; placing an order calls recordOutbound with reason: "SALE"; cancelling/restocking an order calls recordInbound with reason: "CUSTOMER_RETURN". Places orders, claims stock and SKU units against them, and manages their lifecycle. Routes live in src/order/order.routes.ts, mounted at /v1/orders.

🔒

⚠
A multi-line order isn't atomic — a later line failing leaves earlier lines already committed. createOrder (order.services.ts:90-198) processes products[] one line at a time: for each inventory-managed line it claims SKU units and calls recordOutbound before moving to the next line.
